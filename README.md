# 汇报 PPT 制作步骤

## 我为什么这样做

做 PPT 的 skills，我试过一些，但就我自己的使用体验来说，效果都不太理想。常见的问题是排版不够协调，一页里放了大段文字，却只有少量图示。

我的感觉是，直接让大语言模型生成 PPT 时，它对最终整页画面的把握和视觉反馈往往不够充分，容易出现“内容写全了，但页面不好看”的情况。文生图模型在整体构图、图文搭配和视觉呈现上更有优势，更容易做出图示丰富、版式完整的页面。

所以，我现在会先用文生图模型做出每一页的样子，再根据汇报的重要程度，决定是否继续还原成可编辑的 PPT。

我这次主要用到两个工具：

- **GPT-image 2.5**：生成和修改每一页的 PPT 图片。
- **GPT-6.1 Sol + Codex**：梳理文献、调整大纲、组织生图任务、拼合 PPT，以及后续的可编辑还原和汇报稿制作。思考强度设为“极高”。

使用方式上，如果是用自己订阅的 ChatGPT 账号登录 Codex，且当前环境支持内置生图，整套流程都可以在 Codex 里完成，因为它能直接调用 OpenAI 的文生图模型。

如果通过 API 登录，或使用其他底座模型，而当前环境无法直接生图，也可以先让模型输出每一页的生图提示词，再把提示词和参考图交给 ChatGPT 网页端生成图片。图片生成后，再交回 Codex 拼合成 PPT、继续精修。

整个流程分九步。前四步得到图片版 PPT，后五步用于精修。

## 一、生成图片版 PPT 初稿

### 第一步：定大纲

把要汇报的论文 PDF，以及自己觉得好看的 PPT 排版参考图，一起交给 GPT-6.1 Sol。先确定讲什么、怎么讲，再开始制作页面。

可以直接用这段提示词：

```text
请基于上传的论文 PDF 和风格参考图，规划一份 16:9 中文学术组会 PPT，专业术语可用英文，页数以讲清重点为准。

按文献实际内容组织背景、科学问题、研究设计与方法、关键结果、机制模型、创新点、讨论及总结展望。参考图片的配色、字体和版式，减少长段文字，突出结论和数据，合理使用原文图表、数据可视化、流程图及机制示意图。

请输出总页数及逐页方案：标题、核心结论、展示内容、图表出处和排版建议。暂不生成 PPT 文件。
```

### 第二步：修改大纲

逐页检查大纲：有没有漏掉重要结果，方法是否交代清楚，前后顺序是否合理，哪些地方需要补充解释。直接指出具体页码和问题，让模型修改，直到汇报逻辑顺畅。

例如：

```text
请在第 5 页补充实验分组、对照设置和研究目的，说明结果如何支持结论。必要时拆页并更新后续页码。
```

这一步尽量把内容定下来，后面就能少返工。

### 第三步：定视觉风格

大纲确认后，先让生图模型做四套风格预览。用相同的几页内容比较不同风格，更容易看出自己喜欢哪一套。

```text
请用 GPT-image 2.5，基于已确认的大纲和参考图生成四套 16:9 学术 PPT 缩略预览，主题配色各不相同，风格清爽、专业。

每套用相同的代表性页面，按幻灯片浏览视图排列。先展示预览，待我选定后再制作完整 PPT。
```

### 第四步：确认风格，输出图片版 PPT

选定一套风格后，再生成全部页面，并拼合成 PowerPoint。下面以选择第二套为例，实际使用时按自己的选择改。

```text
采用第二套风格，按已确认的大纲，用 GPT-image 2.5 逐页生成独立的高清 16:9 图片，保持全套风格一致。

请将图片按顺序铺满对应幻灯片，拼合为完整 PowerPoint，在当前工作目录输出 .pptx 文件，并保留逐页图片。
```

到这里得到的是**图片版 PPT**：可以正常放映，但页面里的文字、箭头和图形还不能单独编辑。

一般的课程汇报，对照原文核对无误后，做到这一步通常就够用了。对于比较重要、需要反复调整的组会或正式汇报，我会继续往下做。

## 二、精修为可编辑版本

### 第五步：针对性修改每一页图片

逐页查看生成的图片，重点检查文字、图表和逻辑关系。哪里有问题，就明确指出位置、错误和修改方式；有合适的截图，也可以一起提供。

例如：

```text
请参考上传的截图，修改第 5 页关系图：将 A 指向 B 改为 B 指向 A。保留其他内容和风格，重新生成这一页并替换进 PPT。
```

先把图片本身改到满意，再开始还原可编辑版本。

### 第六步：把每页图片还原成可编辑 PPT

这一轮的目标是尽可能保留原来的视觉效果，同时把文字、方框、箭头等常用元素拆成可以单独编辑的对象。复杂的图形或图像可以保留为图片。

```text
请逐页将当前图片版 PPT 还原为可编辑的 PowerPoint，尽量还原文字、配色、布局和视觉层次。

文字、方框、箭头及简单图形用原生可编辑元素重建；复杂图像可裁剪保留。逐页对照原图检查遗漏、对齐和遮挡，输出 .pptx 文件。
```

这里的“还原”需要逐页检查，不能默认一次就能完全复刻。尤其要确认文字是否真的能编辑，箭头方向和图形关系有没有变化。

### 第七步：统一全局格式和排版

还原后再做一次全局调整，把主标题、页码、字体和装饰元素统一起来。

```text
请以第 X 页为样式基准，统一整份 PPT：固定主标题和右下角页码的位置，统一标题及正文的字体、字号和四周装饰图形的风格。

调整对齐与间距，检查文字溢出、重叠和遮挡，保留必要的版式差异，输出 .pptx 文件。
```

其中“第 X 页”换成自己最满意、适合作为全局参考的一页。

### 第八步：生成汇报稿，写入备注

让模型同时读取每页内容并查看页面截图，结合原文生成汇报稿，再直接写入对应幻灯片的备注。这样讲解图表时，也能对应到页面里实际展示的内容。

```text
请读取每页 PPT 并查看页面截图，结合原论文，为每页撰写中文汇报稿，写入对应幻灯片的备注，输出含备注的 .pptx 文件。

讲稿要适合口头表达，讲清图表与结论，衔接自然、学术严谨，避免照读页面或补充无依据的结论。
```

### 第九步：按自己的口语习惯修改汇报稿

最后我会自己顺着 PPT 讲一遍。把拗口的句子改成平时会说的话，删掉重复内容，补上自己习惯的过渡，也顺便检查有没有“稿子写得很顺，但其实没讲明白”的地方。

这一遍最好真的开口讲，才能发现哪里需要停顿、哪里解释太快，以及整场汇报是否超时。

论文中的数据图优先使用原文图表。无论做到哪一步，数字、术语、图注和机制关系都要自己核对。图片看起来漂亮，只代表视觉效果过关，内容还需要对照原文确认。
